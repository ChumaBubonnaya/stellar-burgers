# Stellar Burgers

Учебное приложение космической бургерной на React и TypeScript. Проект выполнен на основе стартового набора `ChumaBubonnaya/stellar-burgers`; исходные UI-компоненты и оформление сохранены, прикладная логика реализована в этом проекте.

## Возможности

- Каталог ингредиентов с сервера, вкладки категорий и подробный состав.
- Конструктор: замена булки, добавление нескольких одинаковых начинок, перестановка, удаление, счётчики и динамическая стоимость.
- Регистрация, вход, выход, восстановление пароля и восстановление сессии при запуске.
- Защищённые страницы, возврат после входа на ранее запрошенный маршрут.
- Редактирование профиля с сохранением и отменой изменений.
- Отправка заказа с авторизацией; очистка конструктора только после успешного ответа.
- Общая лента, личная история, статусы, состав, цены и статистика заказов.
- Детали ингредиента и заказа открываются модально при переходе из списка и отдельной страницей по прямому адресу или после перезагрузки.
- Обработка ошибок и состояний ожидания. Повторная загрузка каталога и ручное обновление ленты.

Заказы обновляются через REST API каждые 10 секунд, пока страница видима, и при возвращении в окно. После успешного оформления заказа лента и история запрашиваются сразу. Для авторизованных запросов предусмотрено автоматическое обновление истёкшего access token; параллельные запросы используют один запрос обновления.

## Запуск

Нужен Node.js 22.12 или новее. Рекомендуется актуальная LTS-версия Node.js.

```bash
npm ci
npm start
```

Адрес приложения: http://localhost:4000.

В архив включён `.env` с публичным адресом учебного API. При получении проекта через Git создайте `.env` в корне по образцу `.env.example`:

```env
BURGER_API_URL=https://norma.ffapi.ru/api
```

После изменения `.env` перезапустите dev-сервер. Учётную запись можно создать через форму регистрации; реальные личные пароли использовать не требуется.

## Проверки

```bash
npm run typecheck
npm run check
npm test -- --runInBand
npm run build
```

Для браузерных тестов:

```bash
npx playwright install chromium
npm run e2e
```

Playwright сам запускает приложение на порту 4000. Тесты используют отдельные браузерные сессии и подменяют ответы API, поэтому не создают реальные учётные записи и заказы. В проекте 19 модульных тестов и 17 браузерных сценариев: конструктор, модальные окна, авторизация, профиль, обновление токена, восстановление пароля, оформление заказа, лента и история.

Продакшен-сборка создаётся в `dist`. Её можно проверить командой `npm run preview`. При размещении на хостинге настройте возврат `index.html` для неизвестных файловых путей, чтобы прямые ссылки React Router работали. Конфигурация рассчитана на размещение в корне домена.

## Маршруты

| Адрес                                 | Назначение               | Доступ                                     |
| ------------------------------------- | ------------------------ | ------------------------------------------ |
| `/`                                   | Конструктор              | Все                                        |
| `/ingredients/:id`                    | Детали ингредиента       | Все                                        |
| `/feed`                               | Лента заказов            | Все                                        |
| `/feed/:number`                       | Детали заказа            | Все                                        |
| `/login`, `/register`                 | Вход и регистрация       | Гости                                      |
| `/forgot-password`, `/reset-password` | Восстановление пароля    | Гости; новый пароль — после запроса письма |
| `/profile`                            | Данные профиля           | Авторизованные пользователи                |
| `/profile/orders`                     | Личная история           | Авторизованные пользователи                |
| `/profile/orders/:number`             | Детали заказа из истории | Авторизованные пользователи                |
| Остальные адреса                      | Страница 404             | Все                                        |

## Организация кода

- `src/components/ui` — представление, основанное на стартовом наборе.
- `src/components` и `src/pages` — подключение данных и обработчиков.
- `src/services/slices` — шесть областей Redux: каталог, конструктор, сессия, лента, история, заказ и его детали.
- `src/services/selectors.ts` — получение данных из хранилища и расчёт стоимости.
- `src/hooks` — обновление заказов и общее состояние форм авторизации.
- `src/utils/burger-api.ts` — HTTP-запросы и обновление токена.
- `tests` — браузерные тесты и фикстуры; `*.test.ts` рядом с кодом — модульные тесты.

Пароль не сохраняется в Redux. Access token хранится в cookie, refresh token — в localStorage в соответствии с устройством учебного API. Сведения о пользователе и история очищаются после успешного выхода.
